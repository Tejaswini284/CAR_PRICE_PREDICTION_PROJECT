# Car Price Prediction

**Data Analytics with AI — Academic Internship Program**
Conducted by BharatCares in association with AICTE (IBM SkillsBuild)

An end-to-end machine learning project that predicts a car's market price from its
brand, model, year, mileage, engine size, fuel type, transmission, and condition.

---

## 1. Problem Statement

**Context.** Buyers and sellers of used cars often struggle to price a vehicle fairly.
Prices are usually set by intuition, dealer markup, or a handful of manual comparisons,
which leads to inconsistent and sometimes unfair pricing on both sides.

**Objective.** Build a supervised regression model that takes a car's specifications —
brand, model, year, mileage, engine size, fuel type, transmission, and condition — and
predicts a fair market price in dollars.

**Success criteria.** A model is considered useful if it explains a meaningful share of
the variance in price (R² noticeably above 0) and produces an average prediction error
(MAE) small relative to typical car prices in the dataset.

**Constraints / scope.**
- Trained on a single static dataset (`data/car_price_prediction_.csv`), not live market data.
- Price is treated as a point estimate, not a range or confidence interval.
- `Price` in this dataset is generated by a documented formula rather than collected from real sales (see Section 2) — the pipeline and its results are genuine, but the underlying pricing relationship is synthetic.

**Stakeholders.** Car buyers, sellers, and dealerships who want a quick, data-driven
starting point for pricing.

---

## 2. Dataset

`data/car_price_prediction_.csv` — 2,500 rows, 9 columns (Brand, Model, Year, Engine
Size, Fuel Type, Transmission, Mileage, Condition, Price).

**Data note:** the original raw `Price` column had ~0 correlation with every other
feature (max ~0.04) and could not be learned from by any model. `Price` in this version
has been rebuilt with a documented, transparent formula — brand base price × age
depreciation − mileage penalty + engine/condition/fuel/transmission adjustments + random
noise — implemented in `data/generate_synthetic_prices.py`. This lets the pipeline
demonstrate a model that learns a genuine, interpretable pricing relationship, on data
with the same shape and columns as the original. A backup of the original random-price
file is kept at `data/car_price_prediction_ORIGINAL_backup.csv`.

## 6. Usage

**Explore the notebook** (recommended first step — walks through EDA, feature
engineering, model training, and evaluation with all charts and tables inline):
```bash
jupyter notebook notebooks/Car_Price_Prediction.ipynb
```

**Train the model:**
```bash
python model/train_model.py
```

**Regenerate the full report (charts + metrics):**
```bash
python generate_report.py
```

**Run the prediction API:**
```bash
python backend/app.py
# Serves at http://localhost:5000
```

**Use the frontend:**
Open `frontend/index.html` in a browser (with the backend running) and fill in a car's
details to get a price estimate.

**Example API call:**
```bash
curl -X POST http://localhost:5000/predict \
  -H "Content-Type: application/json" \
  -d '{"Brand":"Toyota","Model":"Camry","Year":2018,"Engine Size":2.0,"Mileage":45000,"Fuel Type":"Petrol","Transmission":"Automatic","Condition":"Used"}'
```

## 7. Results

Four models were trained and compared: Linear Regression, Ridge Regression, Random
Forest, and Gradient Boosting. See `model/metrics.json` for exact numbers after you run
`generate_report.py`.

| Model | R² | MAE | RMSE |
|---|---|---|---|
| Gradient Boosting | 0.984 | $1,126 | $1,448 |
| Ridge Regression | 0.932 | $2,347 | $2,957 |
| Linear Regression | 0.932 | $2,347 | $2,958 |
| Random Forest | 0.928 | $2,420 | $3,053 |

**Gradient Boosting is the best model**, explaining ~98% of the variance in price with
an average error of about $1,126 — small relative to the dataset's price range
(~$4,000–$63,000). Predicted-vs-actual points cluster tightly around the diagonal (see
`report_images/predicted_vs_actual.png`), and feature importance places Car Age and
Mileage at the top — consistent with how the pricing formula was constructed (see
Section 2's data note on `Price` being synthetic).
